# Phase 2G Gold schema -- `cases.jsonl`

One JSON object per line. Generated by `scripts/generate_phase2g_gold.py`;
loaded and validated by `src/evals/patent_prior_art/dataset.py`
(`PatentGoldCase`). Expectations are authored from the case's own world; the
scorer (`src/evals/patent_prior_art/runner.py`) also re-derives identity,
chronology and family counts independently of the graded code.

| Field | Meaning |
|---|---|
| `case_id` | `PG-NNN` |
| `language` | `en`, `ar` or `mixed` -- the language of the claims |
| `categories` | Specification section 35 categories this case exercises (72 names in `REQUIRED_CATEGORIES`) |
| `claims` | Canonical claims `{claim_id, claim}`. Also used to build the populated upstream Phase 2B-2F world. |
| `privacy` | Identity strings (`person_names`, `school_names`, `emails`, ...) that must never reach a query |
| `cutoff` | Explicit search cutoff `YYYY-MM-DD`, or `null` for none |
| `provider` | `EPO_OPS` (scripted office), `NONE` (no credentials) or `WIPO_PATENTSCOPE` (must be refused) |
| `settings` | Overrides of `PatentResearchSettings` |
| `model_terms` | Scripted, untrusted model expansion terms `{term, original_text, kind}`, or `null` for no model |
| `records` | Patent records the office holds: `ref` (`CC.NUMBER.KIND`), title, the four dates, parties, IPC/CPC, `family_id`, abstract, claims, description (+ languages), `malformed` |
| `search_default` | Office search behaviour for every query: `records`, `total`, `failure`, `leading_failures`, `payload` (`MALFORMED`, `FAULT_400`, `FAULT_403_QUOTA`, `FAULT_500`), `http_status`, `ignore_range` |
| `search_by_strategy` | Per-`PatentSearchStrategy` override of `search_default` |
| `families` | Family service response per record ref: `family_id`, `members`, `earliest_priority`, `available`, `failure` |
| `texts` | Per record ref and content type: `published`, `failure` |
| `resume_before` | Interrupt the graph before this node and resume from the checkpoint |
| `rerun` | Re-invoke the finished graph and require an identical patent run |
| `tamper` | Negative controls applied to the finished run that the contract must refuse |
| `expected` | `outcome`, `coverage_status`, `publication_keys`, `independent_family_count`, `family_status`, `family_members`, `time_qualification`, content availability maps, `title_only`, `excluded_claims`, query bounds and strategies, `model_assisted`, `rejected_query_reasons`, error kinds, attempts, retries, `pages_requested` |

Minimums: 128 cases, Arabic >= 24, mixed >= 16, every category covered.
Never generate pipeline output and then declare it correct.
