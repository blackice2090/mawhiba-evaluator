# Claim-evidence scoring Gold schema — v1

One JSON object per line in `cases.jsonl`. Regenerated by
`scripts/generate_phase2f_gold.py`; edit the generator, not the data file.

Each case describes a complete synthetic upstream world — claims, Phase 2B
logical sources with their canonical identifiers, Phase 2C verified evidence,
Phase 2D alignments — and the **exact** numbers a correct Phase 2F pass must
produce from it. The world is materialized through the Phase 2E Gold builders,
so a Phase 2F case *is* a Phase 2E world plus score expectations.

**Authoring rule.** Expectations are derived from the described input by
applying `CLAIM-EVIDENCE-SCORING-POLICY-V1` by hand: how many material
components the claim has, which are adequately covered in which direction, and
how many independent studies back each. Numbers are exact integer basis points,
never tolerances. Output is never generated and then declared correct — when the
engine disagreed with an expectation during development, the input was
re-examined and the discrepancy explained before either side changed.

All content is synthetic. No real paper, DOI, author, dataset or student
identity appears. Arabic and mixed-language cases carry Arabic only as *data*,
in claim text and excerpt value positions, never translated.

## Case fields

| field | type | meaning |
|---|---|---|
| `case_id` | `CES-\d{3,}` | unique within the dataset |
| `language` | `ar` \| `en` \| `mixed` | drives the per-language metric subgroups |
| `categories` | list of strings | at least one; the coverage minimums are asserted by name in the test module |
| `claims` | list | `claim_id` (`C-\d{3,}`), `claim`, optional `claim_type` |
| `sources` | list | one Phase 2B logical source each — see below |
| `evidence` | list | one Phase 2C evidence item each — see below |
| `alignments` | list | one Phase 2D relation each — see below |
| `alignment_status` | `ClaimAlignmentStatus` | defaults to `COMPLETED` |
| `sufficiency_not_ready` | bool | score against a research run whose Phase 2E pass never completed |
| `direct_mode` | bool | call the pipeline below the graph, for shapes a validated run record cannot hold |
| `direct_kind` | `cross_run` \| `unknown_inventory` | which below-the-graph shape; required with `direct_mode` |
| `resume_after_node` | node name \| null | interrupt the Phase 2F graph before this node and resume from the checkpoint |
| `rerun` | bool | invoke the finished graph again, and score an independent second run of the same world |
| `fingerprint_pair` | `<case_id>:same` \| `<case_id>:differ` \| null | the partner case this one must match or differ from in `input_fingerprint` |
| `expected` | object | see **Expectation fields** |
| `notes` | string | why this case exists and what its number means |

### `sources[]`

Inherited unchanged from the Phase 2E Gold schema: `key`, `title`, `doi`,
`openalex_id`, `semantic_scholar_id`, `arxiv_id`, `pmid`, `canonical_url`,
`source_type`, `is_retracted`, `publication_year`, `providers`, `orphan`.

Canonical identity comes from the strongest identifier, never from a title
(ADR-009). Two source entries sharing one identifier are deliberately the
*same* underlying work seen twice — the duplicate-collapse case. `orphan: true`
omits the source from the run so its evidence has no resolvable identity.

### `evidence[]`

`key`, `source`, `excerpt`, `evidence_type`, `content_kind`
(`ABSTRACT` | `PARTIAL_TEXT` | `FULL_TEXT`), `is_retracted`,
`missing_from_run`.

`content_kind` drives the reliability content-scope ceiling: only `FULL_TEXT`
can reach `HIGHER_RELIABILITY`. `missing_from_run: true` builds the evidence id
but omits the item, so an alignment references evidence the run does not hold.

### `alignments[]`

`claim_id`, `evidence`, `relation`, `components[]` (`text`, `judgment`),
`foreign_run`, `hash_mismatch`, `fabricated_anchor`.

Component anchor offsets are derived from the claim text by the builders, so
every anchor satisfies `claim.claim[start:end] == anchor_text` by construction.
`fabricated_anchor` records claim text that does **not** occur in the claim,
which leaves the Phase 2E component inventory `INCOMPLETE` and therefore
withholds the Phase 2F primary scalar.

Relation/component consistency is Phase 2D's rule and is enforced by its
contract: `SUPPORTS` needs only supporting components, `PARTIALLY_SUPPORTS`
needs a supporting component plus a contextual or unresolved one, `MIXED` needs
both supporting and contradicting, `NOT_RELEVANT` needs none.

## Expectation fields

All indices and dimensions are **integer basis points**: `10000` is `100.00`.
Basis points rather than display values because a one-basis-point disagreement
is exactly the arithmetic drift this dataset exists to catch.

| field | type | meaning |
|---|---|---|
| `status` | string \| null | expected `ClaimScoringStatus` of the run |
| `scorecards_total` | int \| null | how many cards the run must hold |
| `support_index_bp` | `{claim_id: int}` | exact support index |
| `contradiction_index_bp` | `{claim_id: int}` | exact contradiction index |
| `support_dimensions_bp` | `{claim_id: [cov, corr, direct]}` | the three support dimensions, in order |
| `contradiction_dimensions_bp` | `{claim_id: [cov, corr, direct]}` | the three contradiction dimensions |
| `disposition` | `{claim_id: ScoreDisposition}` | whether a primary scalar is issued, and why not |
| `final_support_index_bp` | `{claim_id: int}` | the issued primary scalar |
| `final_withheld` | list of claim ids | claims that must issue **no** scalar |
| `reliability` | `{claim_id: ReliabilityPosture}` | expected posture |
| `covered_components` | `{claim_id: int}` | adequately supported components |
| `contradicted_components` | `{claim_id: int}` | adequately contradicted components |
| `total_components` | `{claim_id: int}` | the complete material component inventory |
| `unexamined_components` | `{claim_id: int}` | components no alignment anchored |
| `saturated_components` | `{claim_id: int}` | components already at maximum corroboration |
| `contributing_groups` | `{claim_id: int}` | distinct supporting independence groups |
| `reason_codes` | `{claim_id: [code]}` | codes that must all be present |
| `forbidden_reason_codes` | `{claim_id: [code]}` | codes that must be absent |
| `withheld_reasons` | `{claim_id: [code]}` | codes that must appear in `withheld_reasons` |

### `final_support_index_bp` versus `final_withheld`

These two fields are how the dataset states the difference between `0` and
`None`, which is the distinction the phase most needs to keep:

- a claim in `final_support_index_bp` **must** issue exactly that scalar — and
  `0` is a legitimate value there, for a fully contradicted claim whose support
  genuinely was evaluated and genuinely is zero;
- a claim in `final_withheld` **must** issue `None`.

A claim listed in both is rejected by the case validator: a scorecard does
exactly one of the two.

## Category coverage minimums

The test module asserts all 64 specification categories by name, so a
regenerated dataset cannot quietly drop one. The dataset currently carries 81
distinct categories across 145 cases.

Language minimums, asserted in the test module: `ar >= 28`, `mixed >= 20`,
total `>= 144`. Current: en 55, ar 45, mixed 45.

Notable categories and what they pin down:

| category | what it proves |
|---|---|
| `one_component_single_group` | full coverage and directness but half corroboration: 85.00, not 100.00 |
| `two_vs_twenty_groups` | twenty independent studies score exactly what two score |
| `same_doi_multiple_providers`, `duplicate_canonical_source_records`, `multiple_excerpts_same_paper` | duplicates cannot inflate either channel |
| `distinct_doi_same_title` | two DOIs sharing a title are genuinely two studies |
| `one_supported_one_no_evidence` | the unexamined half stays in the denominator: exactly half the score |
| `contested_scalar_withheld` | 85.00/85.00 with `final = None`; a net would report 0 |
| `no_net_collapse` | support and contradiction never merge |
| `zero_vs_none` | an evaluated `0` is not a withheld scalar |
| `rounding_boundary` | thirds of each ceiling, rounded half-to-even per dimension |
| `min_bound`, `max_bound` | 0.00 and 100.00 are both reachable and both bounded |
| `incomplete_inventory`, `unknown_inventory` | neither may receive a primary scalar |
| `fingerprint_sensitivity` | one added independent study changes the fingerprint |
| `checkpoint_resume`, `rerun_idempotency`, `duplicate_scorecard_rejection` | a resume neither loses nor double-counts |
| `cross_run_rejection`, `cross_claim_isolation` | the same evidence scores differently against different claims |
| `prompt_injection_inert` | an instruction in claim text is inert *and* becomes an unexamined component, lowering the score |
| `official_score_separation` | no rubric or project-score field appears on any card |

`unknown_inventory` is reachable only below the graph: the graph assesses only
claims it could resolve, so `CLAIM_NOT_RESOLVABLE` never arises there. The case
uses `direct_mode` with `direct_kind: unknown_inventory` for exactly that
reason — an unreachable-through-the-graph path is the kind that rots unwatched.
